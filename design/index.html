Report tool — five redesigns

Five directions for the same app, all built around the one thing the user actually does: pick a template, say what happened, get a report back. Each is a working HTML mockup — click through the tabs, press the buttons, toggle light and dark.

Nothing in app/ was touched. These are standalone files.

Inspired by Stargate

1 · Aperture

Stargate's Swiss palette applied literally: paper and graphite, hairline rules, no colour accent at all, a fixed left rail with the page title set large and quiet.

  • Rail: Reports · Current report · Templates · Settings
  • Notes and report side by side, one hairline between them
  • Template builder as an indented outline

Guided

2 · Steps

The flow is the app. Three numbered steps across the top, one screen at a time, nothing else visible. Everything configurable hides behind a single “Set up” door.

  • Template gallery → notes → report
  • A real writing state, not a frozen button
  • Hardest to get lost in; most clicks for a repeat user

Editorial

3 · Manuscript

The document is the interface. Notes live in the margin the way you'd scribble them beside a page; the report is a sheet of paper. The template is edited as a ghost of the document it produces — each instruction set in the type size it will come out as.

  • Serif page, warm paper, almost no chrome
  • Formatting bar floats at the bottom
  • Best-looking output; narrowest for long notes

Familiar

4 · Desk

Opens on a home screen that answers “what do I do now” instead of an empty editor. Cards, soft shadows, one blue. Notes and report are two faces of the same card, so they never compete for the screen.

  • Continue-where-you-left-off, recents, template gallery
  • Segmented Notes / Report toggle with a sticky action dock
  • Closest to what a non-technical user already expects

Voice first

5 · Field

For someone standing on a roof with one free hand. A single large mic, a timestamped list of what was said, one big button. Typing is the fallback. Dark by default, large targets, narrow column.

  • Each utterance is its own editable line
  • Reports, templates and settings are bottom sheets
  • Fewest controls on screen of the five

What every design drops

The system-prompt panelShows the user the machinery, not their work. It exists to debug prompt-building; a developer flag is the right home for it.
The JSON-schema panelSame — nobody outside the team can act on it.
“Markdown sent to the model” and the live markdown mirrorThe report on screen already is the document. A second copy in monospace invites the question “which one is real?”. Export still writes markdown.
The whole right-hand paneEvery one of its four states was a developer view. Removing it doubles the room the actual work gets.
The JSON key next to each template fieldAn implementation detail leaking into the field list.
Save / Open / New / Save template / Templates as toolbar buttonsReplaced by a reports list and autosave. “Save” as a decision belongs to 1995.
Provider names (Remote / Local / Stub, base URL, context tokens, GGUF path, timeout)Restated as the only question that matters — do my notes leave this computer? The rest sits under “Server details”.
Node-kind jargon“Optional” → Only sometimes; “Repeat” → Repeats, once per defect; a list's ordered flag → numbered.
